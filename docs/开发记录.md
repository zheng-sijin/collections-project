## 2026-11-16：MySQL 保存与查询剧集播放源

- 目标：在单模块项目中使用 MySQL + MyBatis-Plus 保存一条剧集播放源，并提供新增、查询播放信息接口；只存播放地址，不下载视频。
- 方案：用户确认采用 Controller → Service → Mapper → MySQL，并要求简单步骤合并开发。表 `video_source` 保存标题、集数、线路名、播放类型和播放地址；密码由本机环境变量 `COLLECTIONS_DB_PASSWORD` 提供，不进入仓库。
- 代码：`pom.xml` 加入 MyBatis-Plus Spring Boot 3 starter、MySQL 驱动及 Lombok，并显式配置 Lombok 注解处理器；`application.yml` 配置本机数据源；`CollectionsApplication.java` 扫描 Mapper；新增 `sql/init.sql`、`VideoSource.java`、`VideoSourceMapper.java`、`VideoSourceService.java`、`VideoSourceController.java`。用户要求学习常用工具后，将 `VideoSource` 的手写 getter/setter 改为 Lombok `@Data`。
- 接口：`POST /api/videos/sources` 新增记录，成功返回 HTTP 201 和生成的 ID；`GET /api/videos/sources/{id}/play` 按 ID 查询，不存在返回 HTTP 404。Service 校验必填项、正整数集数、HTTP(S) 地址及 `MP4`/`HLS` 类型。
- 验证：`mvn -q -DskipTests package` 成功。初次联调返回 HTTP 500，运行日志显示 `Access denied for user 'root'@'localhost'`；用户调整 IDEA 运行配置中的密码后反馈运行成功。随后 GET 一个不存在的 ID 返回 HTTP 404，说明数据库查询链路已执行。加入 Lombok 后 `mvn -q clean package` 成功；`javap` 确认编译后的 `VideoSource` 含生成的 getter/setter、`equals()`、`hashCode()` 和 `toString()`。尚未由 agent 独立验证 POST 写入及重启后的持久化。
